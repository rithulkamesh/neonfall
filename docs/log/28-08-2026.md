```rust
let positions: Vec<[f32; 3] > = reader
.read_positions()
.map( | iter| iter.collect())
.unwrap_or_default();

// Get the colors of all objects
let colors: Vec<[f32; 3] > = reader
.read_colors(0)
.map( | colors| colors.into_rgb_f32().collect())
.unwrap_or_else(| | {
let base_color = primitive
.material()
.pbr_metallic_roughness()
.base_color_factor();
vec ! [[base_color[0], base_color[1], base_color[2]]; positions.len()]
});

// We're taking the positions of all the points, and putting it into the vertex matrix.
vertices.extend(
positions
.into_iter()
.zip(colors.into_iter().chain(std::iter::repeat([1.0; 3])))
.map( | (pos, col) | NFVertex::new(pos, col)),
);

// Using the vertices, we're creating an index buffer for optimization
let vertex_count = vertices.len() as u16 - base_vertex;
indices.extend(
reader
.read_indices()
.map( | read_indices| {
read_indices
.into_u32()
.map( | idx| base_vertex + idx as u16)
.collect::< Vec < u16 > > ()
})
.unwrap_or_else(| | {
(0..vertex_count)
.map( | offset| base_vertex + offset)
.collect::< Vec< u16 > > ()
}),
);

// Return (vertices, indices)
```

### GPU instancing from scratch

After loading one cube, I wanted to render several copies without duplicating the cube's vertices and indices. The
important distinction is that the mesh is the shared geometry, while each instance only needs its own transform.

I started with two CPU/GPU representations in
`crates/neon-renderer/src/gpu/instance.rs`:

```rust
pub struct NFInstance {
    pub position: Vec3,
    pub rotation: Quat,
}

#[repr(C)]
#[derive(Copy, Clone, bytemuck::Pod, bytemuck::Zeroable)]
pub struct NFInstanceRaw {
    model: [[f32; 4]; 4],
}
```

`NFInstance` is convenient for the game to construct. `NFInstanceRaw` is the layout sent to the GPU. Its model matrix is
generated from the position and rotation:

```rust
Mat4::from_translation(position) * Mat4::from_quat(rotation)
```

The matrix occupies four `Float32x4` vertex attributes. Those attributes use shader locations `2..=5` and
`VertexStepMode::Instance`, which tells wgpu to advance the matrix once per instance instead of once per vertex.

The existing mesh layout keeps locations `0` and `1` for position and color. The render pipeline now accepts both
layouts:

```rust
buffers: & [
Some(NFVertex::desc()),
Some(NFInstanceRaw::desc()),
],
```

The vertex shader reconstructs the matrix and applies it before the camera projection:

```wgsl
let instance_model = mat4x4<f32>(
    model.model_0,
    model.model_1,
    model.model_2,
    model.model_3
);

out.clip_position =
    camera.view_proj * instance_model * vec4<f32>(model.position, 1.0);
```

On the CPU, `NFState` converts every `NFInstance` to `NFInstanceRaw`, creates an instance vertex buffer, and binds it at
vertex-buffer slot `1`:

```rust
render_pass.set_vertex_buffer(0, self .vertex_buffer.slice(..));
render_pass.set_vertex_buffer(1, self .instance_buffer.slice(..));
```

The final change from one cube to many cubes is the instance range in the indexed draw call:

```rust
render_pass.draw_indexed(
0..self .num_indices,
0,
0..self .instances.len() as u32,
);
```

That reuses the same vertex and index buffers for every copy.

### Making instances part of the mesh API

I initially passed instances separately through `neon_engine::init`, but that made the public engine API expose two
pieces that belong to one renderable object. I moved the instance list onto `NFMesh` instead:

```rust
let mesh = NFMesh::from("./models/cube.glb").with_instances(vec![
    NFInstance::new(Vec3::new(-2.2, 0.0, 0.0), Quat::IDENTITY),
    NFInstance::new(Vec3::new(0.0, 0.0, 0.0), Quat::IDENTITY),
    NFInstance::new(Vec3::new(2.2, 0.0, 0.0), Quat::IDENTITY),
]);

neon_engine::init(config, mesh, camera);
```

`NFMesh` contains the geometry and its placements. The engine only passes the mesh around, while the renderer converts
those placements into an
`NFInstanceRaw` GPU buffer.
