# August 29, 2026

### Textures, but the game can actually touch them now

Yesterday I wired up the renderer side of textures — `NFTextures`, bind groups, UVs from glTF, the whole tutorial 5
shape. But `game/` couldn't do anything with it. You loaded a glb, hoped it had an image baked in, and if it didn't
you got a white 1×1 placeholder. That's fine for faafo, not fine for actually building a game.

So today I pushed texture control up through the engine boundary.

`neon_engine` now re-exports `NFTextureImage`, and `NFMesh` got two builder methods:

```rust
pub fn with_diffuse(self, image: NFTextureImage) -> Self
pub fn with_color_atlas(self, colors: &[[u8; 3]]) -> Self
```

`with_diffuse` is the simple case — one image, one bind group, done. `with_color_atlas` is the hack I needed for the
cube grid demo.

### The one-texture problem

Instancing reuses the same draw call for every cube. That means they also share the same `@group(0)` diffuse texture.
I can't bind 16 different textures without 16 draw calls (not doing that yet).

What I _can_ do: bake every dummy color swatch into a single atlas image at runtime, then tell each instance which
cell to sample from.

Game side, I'm generating colors in HSV so the grid actually looks distinct:

```rust
let mut colors = Vec::with_capacity(instance_count);
for i in 0..instance_count {
    let hue = (i as f32 / instance_count as f32) * 360.0;
    colors.push(hsv_to_rgb(hue, 0.75, 0.9));
}

let mesh = NFMesh::from("./models/cube.glb")
    .with_color_atlas(&colors)
    .with_instances(instances);
```

`NFTextureImage::color_atlas` packs those RGB values into an 8×8 pixel cell grid inside a square texture. For 16 cubes
that's a 4×4 atlas (32×32 pixels total). No PNG files on disk — just `Vec<u8>` built in memory and uploaded when
`NFState` starts.

### Per-instance texture index

Each `NFInstance` now carries a `texture_index`:

```rust
NFInstance::new(position, rotation).with_texture_index(index)
```

That index gets copied into `NFInstanceRaw` and read in the vertex shader. The atlas layout lives in a small uniform on
`@group(0) @binding(2)`:

```wgsl
fn atlas_uv(base: vec2<f32>, index: u32) -> vec2<f32> {
    let grid = u32(atlas.grid);
    let col = index % grid;
    let row = index / grid;
    let cell = 1.0 / atlas.grid;
    return vec2(f32(col), f32(row)) * cell + base * cell;
}
```

So the cube's normal UVs (0..1 across a face) get remapped into one cell of the atlas. Same geometry, same draw call,
different colored faces per instance.

`with_color_atlas` also resets vertex colors to white so the material tint from the glb doesn't muddy the atlas colors.
